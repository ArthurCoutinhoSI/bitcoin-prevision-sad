# Dashboard Contract

**Feature**: `001-bitcoin-forecast-dashboard` | **Version**: 1 | **Date**: 2026-11-08

The dashboard is a local, single-user Streamlit application started with `streamlit run app.py`.
It is a presentation layer only: it loads artifacts, performs one next-day inference, and renders
results. It never trains, tunes or refits a model.

## Data Sources

| Source | Required | Purpose |
|--------|----------|---------|
| `artifacts/model.pkl` | Yes | Fitted production ARIMA model, order, metadata, preprocessing summary, evaluation report and dataset fingerprint |
| `artifacts/evaluation.json` | Optional | Verification copy of the evaluation report; the header metrics and backtest table may be read from the artifact |
| `artifacts/validation_predictions.csv` | Optional | Validation actuals, ARIMA predictions and baseline predictions for the backtest chart |
| `dc.csv` | Yes for the historical chart and fingerprint check | Historical daily records |

**Precedence**: `model.pkl` is the single source of truth for model identity, order, date ranges
and metrics. `evaluation.json` and `validation_predictions.csv` must match the artifact's
`dataset_fingerprint`; a mismatch is treated as `invalid_artifacts`.

**Fingerprint rule**: The `dc.csv` fingerprint must equal the artifact fingerprint. If it differs,
the dashboard must not display a forecast from the stale artifact.

## Required Layout

The dashboard renders one page, top to bottom, with these sections.

### 1. Header

- Title: `Bitcoin Next-Day Forecast`
- Subtitle stating the target (`close_USD`) and horizon (`1 day`).
- Model identity and selected ARIMA order, for example `ARIMA(1, 1, 1)`.
- Data range and last observed date.
- Dataset fingerprint (short form) and artifact creation timestamp.
- A visible, persistent notice: forecasts are estimates, are not guarantees and do not
  constitute financial advice.

The disclaimer and the forecast must be visible together without scrolling on a 1080p desktop
viewport.

### 2. Forecast Summary

- Target date: the day after the last observed date (`2021-01-31` for the provided dataset).
- Predicted closing price in USD.
- Last observed closing price.
- Direction: `Up`, `Down` or `Flat`.
- Percentage change relative to the last observed close, signed and formatted to two decimals.
- Timestamp of when the displayed forecast was generated by the dashboard.

### 3. Historical and Forecast Chart

- Line or area chart of historical `close_USD` against date.
- A distinct point and labeled marker for the next-day forecast on the same axes.
- The forecast marker must be visually distinguishable from historical observations and
  identified in the legend or tooltip.
- X axis: date; Y axis: USD closing price.
- Interactions: mouse hover shows date and value; the chart supports zoom and pan; a reset is
  available through the chart toolbar.
- The chart must not interpolate a line to the forecast point in a way that implies observed data.

### 4. Evaluation Metrics

- A table with rows `ARIMA` and `Naive Last Value` and columns `MAE`, `MSE`, `RMSE`, `R²`.
- Metric values come from the validation period and match `evaluation.json` within `1e-6`.
- `R²` displays as `N/A` when the stored value is `null`.
- A plain-language statement of whether ARIMA outperformed the baseline on validation RMSE.
- Evaluation period date range and observation count.
- A note that metrics are one-step-ahead out-of-sample results and are not a guarantee of future
  accuracy.

### 5. Validation Backtest Chart

- Line chart over validation dates with three series: actual close, ARIMA prediction and naive
  baseline prediction.
- Legend labels: `Actual`, `ARIMA`, `Naive baseline`.
- Same interactions as the historical chart: hover, zoom and pan.
- If `validation_predictions.csv` is absent while `model.pkl` is valid, the section shows an
  informational message and the rest of the dashboard remains usable.

### 6. Insights

- Forecast direction and percentage change in one sentence.
- Model versus baseline statement using validation RMSE.
- Data quality summary: source count, accepted count, duplicates removed, missing values imputed,
  date range.
- Known limitations list from the evaluation report.
- No buy, sell, hold, recommendation, target price range, position sizing or trading signal.

### 7. Footer

- Artifact version.
- Reproduction command: `python -m btc_forecast.cli train --data dc.csv --artifacts artifacts`.
- Disclaimer repeated in short form.

## Interactions

| Interaction | Contract |
|-------------|----------|
| Page load | Load cached resources; perform one next-day forecast; render all sections |
| Chart hover | Show date and USD value for every series at that date |
| Chart zoom/pan | Supported by Altair interactive charts; no server round trip |
| Retry | A `Reload data` button clears caches and reloads artifacts |
| Training | Not available from the dashboard; the user runs the CLI |
| Controls | No model selection, order tuning, date-range filters, uploads or forecast-horizon controls |

No user input changes model behavior. The dashboard is read-only apart from cache invalidation.

## States

| State | Trigger | Required Behavior |
|-------|---------|-------------------|
| `loading` | Initial load or cache clear | Show a spinner or skeleton; do not show placeholder metric values |
| `ready` | Valid artifact, matching fingerprint, successful forecast | Render all sections |
| `missing_artifacts` | `model.pkl` absent | Show an actionable empty state naming the missing file and the training command; do not render a forecast or metrics |
| `invalid_artifacts` | Corrupt, wrong version, missing keys, fingerprint mismatch or non-finite forecast | Show the specific reason in plain language and the remediation; do not render a forecast or metrics |
| `partial_artifacts` | Model valid but evaluation or backtest files missing or mismatched | Render forecast and metrics from the artifact; show an informational message for the unavailable section |
| `data_error` | `dc.csv` missing or unreadable | Show an actionable message naming the file; do not render a forecast |

**Empty-state copy requirements**: name the missing item, state that no forecast is shown on
purpose, and give the exact command to produce it.

**Prohibited in every state**: fabricated prices, zero-filled metrics, stale forecasts from a
different dataset, and buy/sell/hold language.

## Performance

- First content visible within 5 seconds for 1000 records in the reference environment.
- Cached reloads render within 2 seconds.
- Next-day inference completes within 100 ms after the model load.
- Chart rendering must not re-read artifacts on every widget interaction.

## Language and Formatting

- Presentation language: English, consistent with the project documentation.
- Currency values: `USD` with two decimals and thousands separators.
- Percentages: signed, two decimals, with `%`.
- Dates: ISO `YYYY-MM-DD` in tables and tooltips; human-readable labels in prose.
- Metric names: `MAE`, `MSE`, `RMSE`, `R²`.
- Terminology is fixed: `Naive Last Value` for the baseline, `ARIMA` for the model, `validation`
  for the held-out 20%.

## Accessibility

- Do not rely on color alone to distinguish the forecast marker or the backtest series; use
  labels, markers or line styles.
- Every chart has a title and axis labels.
- Text contrast follows Streamlit defaults; no custom low-contrast theme.
- Tables have header rows and readable numeric formatting.

## Out of Scope

- Live data feeds, exchange connectivity, order placement or portfolio tracking.
- Authentication, multi-user sessions or remote deployment.
- Model training, tuning or artifact regeneration from the UI.
- Additional pages, filters or forecast horizons.
- Buy, sell or hold recommendations, price targets or trading signals.
